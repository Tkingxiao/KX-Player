# AI 工作台优化方案与第一批交付规范

## Design Read

把 AI 翻译页从“功能都在，但用户要自己猜顺序”的工具箱，收敛成一条可读、可恢复的工作流：先定范围，再确认接入，再扫描，再执行，最后处理异常。

## 锁定方向

沿用 `.ulpi/design/DESIGN.md` 的 **technical / utilitarian + aurora dark**。不新增渐变、玻璃拟态、装饰性卡片或第二套颜色。第一批只使用现有 token、表格和工序轨道语汇。

## 分批方案

### 第一批：顺序可见、空态可行动、失败不静默（本次执行）

目标：让第一次使用的人能在 5 秒内知道下一步，且扫描/测试连接失败时能看见原因。

1. **全局工作流提示**
   - 在工作台身份栏增加紧凑的 4 步状态带：选择范围、配置接入、扫描字幕、执行翻译。
   - 状态只由现有事实源推导：`aiFolder`、`aiModel`、`scanning`、队列状态。
   - 旁边给出一句“当前建议”，不新增第二事实源，不抢主按钮。
2. **字幕队列操作顺序**
   - 主动作固定放在操作区最右侧：开始翻译 / 翻译选中。
   - 停止、重试失败、清除已完成等次级动作保持在主动作左侧，降低误触与认知跳跃。
3. **扫描空态变成可执行状态**
   - 记录本次扫描发现总数，区分“未选目录”“扫描中”“没有字幕”“已有字幕但都已翻译”。
   - 已没有待翻译项时，明确引导到“译文管理”，不让用户误以为扫描失效。
   - 重复点击扫描在上一轮完成前不再启动第二轮。
4. **接入测试错误闭环**
   - `aiPing` reject 时把异常转换成可读结果，保留端点体检提示，不再只恢复按钮状态。

### 第二批：队列恢复与批量处置

- 失败行支持“仅失败项 / 选中项 / 全部可重试项”的明确范围预览。
- 译文管理增加“待处理优先”默认视图、源/译文路径差异提示、批量操作影响预览。
- 任务离开页面后的状态查询与恢复，避免关闭标签后失去进度。

### 第三批：接入配置和成本护栏

- Provider 配置按“连接参数 / 发送策略 / 安全策略”分组，默认折叠低频参数。
- 开始前显示预计文件数、分块数和并发档位；长任务支持暂停/继续。
- 增加请求预算、连续超时阈值和模型响应异常的可解释提示。

### 第四批：大规模与可访问性

- 大目录扫描/译文管理改为分页或虚拟列表。
- 完整键盘路径、焦点回收、`prefers-reduced-motion` 和错误重试 action 统一封装。

## 第一批验收标准

- 用户未选目录、未配置模型、扫描中、无待翻译项时，页面均显示明确的下一步或原因。
- 扫描按钮重复点击不会启动并行扫描。
- 点击“测试连接”遇到 rejected Promise 时，界面显示 `✗ <错误原因>`，按钮可再次点击。
- 字幕队列的主动作在视觉上唯一且顺序稳定；已有按钮行为不改变。
- 亮/暗主题、窄窗口、SSR 白屏回归不受影响。

## 组件与实现边界

- 允许修改：`AiTranslateView.vue`、`AiApiPane.vue`，以及新增一个仅展示工作流状态的 `AiWorkflowBar.vue`。
- 不允许在本批改动 Rust AI 协议、路径闸门、缓存和任务事件契约；这些已经有安全/兼容性门禁。
- 不引入依赖，不改变现有 IPC 命令和公开类型。
- 所有可见文案使用现有中文产品语气，不使用装饰性营销词。

## Design Pre-Flight

- [x] 复用锁定色板、字体、间距、圆角和动效；不增加字面色值。
- [x] 不引入紫蓝渐变、玻璃拟态、嵌套卡片、三等分营销卡片或装饰性状态点。
- [x] 覆盖未选目录、扫描中、空结果、接入失败和窄窗口状态。
- [x] 主导航仍为 4 个工种，第一批不增加顶层入口。
- [x] 工作流条是读数，不进入 Tab 顺序；按钮仍保留可见 focus。
- [x] 只保留一处工作台签名进度光泽，不新增发光动画。

自评：distinctiveness 3/4；hierarchy 4/4；consistency 4/4；accessibility 3/4；state coverage 4/4；copy 3/4；restraint 4/4；motion 4/4。总分 29/32。低于 4 的项属于当前项目既有 UI 基础能力，本批通过复用现有语义和不增加动画控制风险。

## Build handoff

Implement exactly this spec. Theme the implementation with `.ulpi/design/DESIGN.md` tokens. Do not redesign or re-implement the existing design language. Keep IPC contracts unchanged and run the project's frontend checks before handoff.

## 第二批执行记录

本批先落地两个不改 IPC 的高收益切片：

- 字幕队列支持“全部待翻译 / 失败项 / 已选可翻”的明确启动范围，开始按钮只显示当前范围数量。
- 译文管理默认打开“待处理”，批量操作条显示可重译、现存译文、可删原文数量，并提示源文件与译文是否位于不同目录。

“离开页面后的任务状态查询与恢复”暂不伪装成已完成：当前后端只有事件流和取消命令，没有任务快照查询契约。下一步需要先增加可重放的任务快照，再接入页面恢复，避免把后台运行中的任务重新猜一遍。
